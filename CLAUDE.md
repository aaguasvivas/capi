# CAPI

Dominican dominoes online: 1v1 or 2v2, real-time multiplayer. Live at https://playcapi.com and as an iOS/Android app.

## Layout (monorepo, npm workspaces)
- `apps/web` (Next.js, deployed to Vercel) and `apps/mobile` (Expo)
- `apps/mobile` holds its own `app.json` and `eas.json`; run every expo/eas command from `apps/mobile` under Node 20, never from the repo root
- `apps/mobile/targets/messages`: the CapiMessages iMessage extension (Swift). The config plugin compiles it into the app at prebuild; it is never opened as its own project
- `apps/mobile/plugins`: Expo config plugins that run at prebuild (`withMessagesExtension.js` adds the extension target, `withFmtConstevalFix.js` patches fmt for Xcode 26)
- `apps/mobile/ios` and `apps/mobile/android` are generated by `expo prebuild` and gitignored; edits there vanish on the next prebuild, so change `app.json`, `plugins/`, or `targets/` instead
- `apps/mobile/scripts`: icon and store asset generators; they need `rsvg-convert` (see docs/PLAYBOOK.md)
- `packages/engine` (pure TS game rules + board layout) and `packages/i18n` (shared strings in src/strings.ts)
- `supabase/` (backend: db, auth, realtime)
- Docs: start at `docs/README.md` for the reading order

## Commands
- Web dev: `npm run dev:web`
- Web build: `npm run build:web`
- Mobile: `npm run start:mobile`
- Tests: `npm test` (engine suite incl. fuzz invariants), `npm run test:all` (engine, then web and mobile suites)
- Verify: `npm run verify` (test:all plus an em-dash grep over app source, packages, and docs)
- Types: `npm run typecheck` (`tsc --noEmit` in engine, web, and mobile; run under Node 20)

## Languages
EN/ES with Dominican flavor. Shared strings live only in packages/i18n; do not hardcode strings in apps. The one exception is `apps/mobile/targets/messages/CapiStrings.swift`, a hand-kept mirror of the few keys the Messages extension renders outside the webview; when one of those keys changes in packages/i18n, update the Swift mirror in the same commit.

## Rules
- No em dashes in user-facing text.
- Real-time logic changes need testing with two clients, not one.
- Engine changes: `npm test` includes an invariant fuzz suite (packages/engine/__tests__/invariants.fuzz.test.ts) that plays full seeded games and checks tile conservation, scoring math, turn order, and determinism after every move. A failure prints the seed; reproduce with that exact seed.
